Quickstart Guide

Vault is a highly available distributed storage engine. It runs best in a containerized environment. This guide shows how to spin up a local 3-node cluster.

1. Prerequisites

You must have Docker and Docker Compose installed on your system.

2. Launch the Cluster

Navigate to the project root directory and run:

docker-compose up -d --build

This spins up:

  • 3 Vault Nodes (Ports: 8081, 8082, 8083)
  • 1 PostgreSQL instance (Port: 5432)
  • Prometheus & Grafana (Port: 3000)

3. Verify Cluster Health

Check the custom health endpoint to ensure the cluster has elected a leader and established quorum:

curl -s http://localhost:8081/actuator/health

You should see "status": "UP" along with cluster topology details.

S3-Compatible API Reference

Vault includes a drop-in S3-compatible layer. You can point the AWS CLI, boto3, or the AWS JS SDK directly at Vault without changing any application logic.

Upload an Object

PUT /s3/{bucket}/{key}

Vault automatically handles quorum replication in the background.

aws --endpoint-url http://localhost:8081/s3 \ s3 cp local-image.png s3://my-bucket/image.png

Note: Currently, authentication is bypassed on the `/s3/` endpoint to make local development seamless. In production, place Vault behind an Nginx proxy or API Gateway.

Download an Object

GET /s3/{bucket}/{key}

Streams the object directly from disk. If the local replica is corrupt, Vault performs a quorum read and auto-repairs the local copy in the background.

aws --endpoint-url http://localhost:8081/s3 \ s3 cp s3://my-bucket/image.png downloaded-image.png

Delete an Object

DELETE /s3/{bucket}/{key}

Places a cryptographically signed tombstone over the object, marking it for asynchronous garbage collection.

aws --endpoint-url http://localhost:8081/s3 \ s3 rm s3://my-bucket/image.png

Postgres-Native Architecture

Vault is engineered for apps that already use PostgreSQL.


  • Relational Integrity: File metadata lives in the object_meta table in your own database. You can join your app tables with Vault's tables seamlessly.
  • Zero-Copy Streaming: Files stream directly from local NVMe drives to the client, avoiding database bloat and Out-Of-Memory (OOM) failures.
  • Raft-inspired Leadership: Nodes use Postgres for distributed locking. If a node dies, another automatically takes over.
  • Self-Healing: Corrupt files (bit rot) are caught by the SHA-256 validator during read operations. The node instantly requests a healthy copy from a peer and repairs its local disk.
